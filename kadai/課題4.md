## 错题解析

### 問2　関係データベースの操作（✗ C → 正解 A）

关系代数三个基本操作的区分：

- **結合（JOIN）**：把 2 个以上的表连接起来生成 1 个表 → A 正确
- **射影（Projection）**：从表中取出特定的**列**（B 把它说成了取行，错误）
- **選択（Selection）**：从表中取出符合条件的**行**（C 把它说成了取列，错误）

记忆方法：射影=列、選択=行，选项 B 和 C 正好把两者说反了。

### 問7　ER 図の構成要素（✗ エンティティ → 正解 属性）

問5〜7 分别指向 ER 图的三个构成要素：

- 問5：方框整体 → **実体（エンティティ）**
- 問6：带鸟脚记号的连接线 → **関係（リレーションシップ）**
- 問7：方框内的「従業員番号・従業員名・連絡先」等项目 → **属性（アトリビュート）**

問5 已经回答了「実体」，問7 指的是实体内部的各个项目，即属性。

### 問9　主キー制約の特徴として適切**でない**もの（✗ A → 正解 C）

主键的特征：不能重复（A）、必须有值 NOT NULL（B）、唯一识别记录（D）——这些都是主键的正确特征。

C「必ず INTEGER 型でなければならない」是错误说法：主键可以是字符串等任意类型（如 商品コード CHAR 型），不要求一定是 INTEGER。题目问的是「適切**でない**もの」，所以答 C。

### 問15　内部結合の説明（✗ B → 正解 A）

**内部結合（INNER JOIN）**：只显示满足结合条件的行 → A 正确。

- B「1 つの SQL 文の中に 2 つの SQL を実行できる」说的是**子查询（サブクエリ）**，不是内部结合
- C「結合する行がない場合は NULL を表示する」说的是**外部結合（OUTER JOIN）**

### 問19　正規化：両方の表に必要な属性（✗ D → 正解 A）

受注台帳（<u>注文番号</u>, 注文年月日, 顧客ID, 顧客名, 顧客住所, 品目, 数量, 送り先, 支払方法, 受注金額）分解为注文表和顧客表时：

- 顧客表的主键是 **顧客ID**
- 注文表要引用顾客，需要把 **顧客ID** 作为外键放进来

所以两个表都需要的属性是 **顧客ID**。注文番号只在注文表中需要；送り先・支払方法按题意「注文ごとに決める」，只属于注文表。

### 問20　参照制約を受けずに実行可能な操作（✗ D → 正解 A）

- 商品 (<u>商品コード</u>, 商品名, 単位, 金額)
- 注文 (<u>注文コード</u>, 商品コード, 注文数, 顧客コード)　※商品コード・顧客コード为外键
- 顧客 (<u>顧客コード</u>, 顧客名, 顧客住所)

- **A. 顧客表への新規レコード追加**：顧客表是被引用方（父表），新增记录不受任何外键约束 → 可以执行 ✓
- B. 商品表のレコード削除：如果该商品被注文表引用，删除会违反参照制約 ✗
- C. 商品コードの変更：同理，被引用的主键值不能随意变更 ✗
- D. 注文表への新規レコード追加：插入的 商品コード・顧客コード 必须已存在于父表中，受外键约束 ✗

## 本次测验知识点总结

- 关系数据库用 2 维表表现数据；操作分为 結合（表连接）・射影（取列）・選択（取行）
- ER 图三要素：実体（エンティティ）・属性（アトリビュート）・関係（リレーションシップ）
- 約束：NOT NULL（必须有值）、PRIMARY KEY（唯一・非空、类型不限）、FOREIGN KEY（在参照元表的 CREATE 文中用 REFERENCES 指定）
- 数据库设计流程：需求访谈 → 概念設計 → 論理設計 → 物理設計
- 結合：INNER JOIN 只显示匹配行；LEFT JOIN 以左表为主，无匹配时右侧为 NULL
- 多:多 关系需要 連関（交差）エンティティ；外键对应的典型关系是 1:多
- 正規化拆表时，父表主键要作为外键保留在子表中（如 顧客ID）
- 参照制約：向父表插入不受限；删除/修改被引用的父表记录、向子表插入引用不存在的键都会受限
