# 2026-06-02 数据库设计笔记

## 中文

本周学习数据库设计中的正规化。正规化是通过分解表结构来消除数据冗余和更新异常的系统化方法。课堂以正規化ワークシート为练习材料，学习了从第一范式到第三范式的步骤。

### 正规化的目的

- 消除重复数据，减少存储浪费。
- 避免插入异常、更新异常、删除异常。
- 提高数据一致性，方便维护。

### 正规化步骤

#### 第一范式（1NF）
- 表中不能有重复的列组。
- 每个字段只保存一个值，不允许存储多值（数组）。
- 每行必须有主键，能唯一识别。

#### 第二范式（2NF）
- 满足 1NF 的基础上。
- 非主键字段必须完全依赖主键，不能只依赖复合主键的一部分。
- 如果存在部分依赖，需要把相关字段提取到单独的表中。

#### 第三范式（3NF）
- 满足 2NF 的基础上。
- 非主键字段之间不能有传递依赖（即非主键字段不依赖另一个非主键字段）。
- 如果存在传递依赖，需要再次拆分表。

### 与表设计的关系

正规化是上周学习的表设计的延伸。ER 图完成概念设计之后，通过正规化检查，可以确认表结构是否合理，是否存在重复数据或依赖关系不正确的问题。

经过正规化处理的表，配合主键和外键约束，可以构建出结构清晰、便于维护的数据库。

### 本周重点

- 正规化的目的是减少数据冗余，避免异常操作。
- 第一范式：消除重复列，确保每个字段只存单一值。
- 第二范式：消除部分依赖，非主键字段完全依赖主键。
- 第三范式：消除传递依赖，非主键字段直接依赖主键。
- 正规化和 ER 图、表设计一起构成数据库逻辑设计的完整流程。

## 日本語

今週はデータベース設計の正規化について学習しました。正規化は、テーブル構造を分解することでデータの冗長性と更新異常を取り除く体系的な方法です。授業では正規化ワークシートを使い、第 1 正規形から第 3 正規形までの手順を練習しました。

### 正規化の目的

- データの重複をなくし、ストレージの無駄を減らす。
- 挿入異常、更新異常、削除異常を防ぐ。
- データの一貫性を高め、保守しやすくする。

### 正規化の手順

#### 第 1 正規形（1NF）
- 繰り返しのカラムグループを持たない。
- 各カラムには 1 つの値のみ保存し、複数の値（配列）を入れない。
- 各行には主キーを設け、一意に識別できるようにする。

#### 第 2 正規形（2NF）
- 1NF を満たしたうえで。
- 主キーでない項目は主キー全体に完全に依存しなければならず、複合主キーの一部だけに依存する部分従属があってはならない。
- 部分従属がある場合は、該当するカラムを別のテーブルに切り出す。

#### 第 3 正規形（3NF）
- 2NF を満たしたうえで。
- 主キーでない項目同士に推移従属があってはならない（主キーでない項目が、別の主キーでない項目に依存しない）。
- 推移従属がある場合は、さらにテーブルを分割する。

### テーブル設計との関係

正規化は、先週学習したテーブル設計の延長にあります。ER 図で概念設計を行った後、正規化の確認を通じて、テーブル構造が適切かどうか、データの重複や依存関係に問題がないかを検証できます。

正規化されたテーブルに主キーと外部キーの制約を組み合わせることで、構造が明確で保守しやすいデータベースを構築できます。

### 今週のポイント

- 正規化の目的はデータの冗長性を減らし、異常操作を防ぐことである。
- 第 1 正規形：繰り返し列をなくし、各カラムに単一の値のみを保存する。
- 第 2 正規形：部分従属をなくし、主キーでない項目を主キー全体に完全に従属させる。
- 第 3 正規形：推移従属をなくし、主キーでない項目は主キーに直接依存させる。
- 正規化は ER 図・テーブル設計とともに、データベース論理設計の一連の流れを構成する。

## English

This week covered normalization in database design. Normalization is a systematic method for decomposing table structures to eliminate data redundancy and update anomalies. The class used a normalization worksheet to practice the steps from First Normal Form to Third Normal Form.

### Purpose of Normalization

- Eliminate duplicated data and reduce storage waste.
- Prevent insertion anomalies, update anomalies, and deletion anomalies.
- Improve data consistency and make the database easier to maintain.

### Normalization Steps

#### First Normal Form (1NF)
- No repeating column groups.
- Each column stores only a single value; multiple values (arrays) are not allowed.
- Each row must have a primary key that uniquely identifies it.

#### Second Normal Form (2NF)
- Satisfies 1NF.
- Every non-key column must fully depend on the entire primary key; no partial dependency on part of a composite primary key.
- If partial dependencies exist, move those columns to a separate table.

#### Third Normal Form (3NF)
- Satisfies 2NF.
- No transitive dependencies between non-key columns (non-key columns must not depend on another non-key column).
- If transitive dependencies exist, split the table further.

### Relationship to Table Design

Normalization extends the table design learned last week. After conceptual design with an ER diagram, applying normalization checks whether the table structure is sound and whether there are problems with redundant data or incorrect dependencies.

Normalized tables, combined with primary key and foreign key constraints, produce a database that is well-structured and easy to maintain.

### Key Points

- The purpose of normalization is to reduce data redundancy and prevent anomalies.
- 1NF: eliminate repeating columns; each column stores only one value.
- 2NF: eliminate partial dependencies; every non-key column fully depends on the primary key.
- 3NF: eliminate transitive dependencies; every non-key column depends directly on the primary key.
- Normalization, together with ER diagrams and table design, forms the complete logical design workflow for a database.
