# 2026-06-02 数据库设计笔记

## 中文

本周学习正規化，使用教育管理系统的受講票数据作为练习例子，从第一范式到第三范式进行逐步拆表。

### 原始数据（非正规化）

受講票包含以下信息，一个受講者对应多条课程记录：

| 受講者ID | 氏名 | コースコード | 実施日 | コース名 | 開催期間 | 料金 | 担当講師 | 緊急連絡先 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 200001 | 秋元 正則 | JV21 | 6/21 | JAVA入門 | 3日間 | 2万 | 佐野次郎 | 080-1234-xxxx |
| 200001 | 秋元 正則 | NT21 | 6/26 | ネットワーク入門 | 2日間 | 2万 | 佐野次郎 | 080-1234-xxxx |
| 200001 | 秋元 正則 | UX31 | 7/11 | UNIX入門 | 1日 | 1.5万 | 小林典子 | 090-2222-oooo |

### 第一范式（1NF）

消除重复列组，确保每行可以用主键唯一识别。以受講者ID + コースコード + 実施日作为复合主键，把数据整理成单一表格形式。

### 第二范式（2NF）

复合主键为 受講者ID + コースコード + 実施日。其中：

- 氏名只依赖受講者ID（部分依赖），需要拆出。

拆分结果：

- **受講者表**（受講者ID → 氏名）
- **受講申し込み表**（受講者ID + コースコード + 実施日）

### 第三范式（3NF）

在 2NF 的基础上，检查非主键字段之间的传递依赖：

- コースコード → コース名、開催期間、料金（コースコードに对课程信息的传递依赖）
- 担当講師ID → 担当講師、緊急連絡先（講師IDに对讲师信息的传递依赖）

拆分后得到以下 5 张表：

| 表名 | 主键 | 主要字段 |
| --- | --- | --- |
| 受講者表 | 受講者ID | 氏名 |
| 受講申し込み表 | 受講者ID + コースコード + 実施日 | （関係テーブル） |
| コース表 | コースコード | コース名、開催期間、料金 |
| コーススケジュール表 | コースコード + 実施日 | 担当講師ID |
| 講師表 | 担当講師ID | 担当講師、緊急連絡先 |

### 本周重点

- 正规化是对实际业务数据进行系统分析，逐步消除冗余的过程。
- 1NF：消除重复列，确保有主键。
- 2NF：消除部分依赖，把只依赖主键一部分的字段拆到单独的表。
- 3NF：消除传递依赖，把非主键字段依赖另一个非主键字段的情况拆出去。
- 最终结果是多张通过主键和外键连接的规范化表。

## 日本語

今週は正規化を学習しました。教育管理システムの受講票データを例にして、第1正規形から第3正規形まで段階的にテーブルを分解する練習を行いました。

### 元データ（非正規化）

受講票には以下の情報が含まれており、1人の受講者に対して複数のコース記録がある：

| 受講者ID | 氏名 | コースコード | 実施日 | コース名 | 開催期間 | 料金 | 担当講師 | 緊急連絡先 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 200001 | 秋元 正則 | JV21 | 6/21 | JAVA入門 | 3日間 | 2万 | 佐野次郎 | 080-1234-xxxx |
| 200001 | 秋元 正則 | NT21 | 6/26 | ネットワーク入門 | 2日間 | 2万 | 佐野次郎 | 080-1234-xxxx |
| 200001 | 秋元 正則 | UX31 | 7/11 | UNIX入門 | 1日 | 1.5万 | 小林典子 | 090-2222-oooo |

### 第1正規形（1NF）

繰り返しのカラムをなくし、複合主キー（受講者ID + コースコード + 実施日）で各行を一意に識別できるよう整理する。

### 第2正規形（2NF）

複合主キーは 受講者ID + コースコード + 実施日。このとき：

- 氏名は受講者IDだけに従属している（部分従属）ため、切り離す。

分割結果：

- **受講者テーブル**（受講者ID → 氏名）
- **受講申し込みテーブル**（受講者ID + コースコード + 実施日）

### 第3正規形（3NF）

2NF の状態で、主キーでない項目同士の推移従属を確認する：

- コースコード → コース名、開催期間、料金（推移従属）
- 担当講師ID → 担当講師、緊急連絡先（推移従属）

これらを切り離すと、最終的に以下の5テーブルになる：

| テーブル名 | 主キー | 主なカラム |
| --- | --- | --- |
| 受講者テーブル | 受講者ID | 氏名 |
| 受講申し込みテーブル | 受講者ID + コースコード + 実施日 | （関係テーブル） |
| コーステーブル | コースコード | コース名、開催期間、料金 |
| コーススケジュールテーブル | コースコード + 実施日 | 担当講師ID |
| 講師テーブル | 担当講師ID | 担当講師名、緊急連絡先 |

### 今週のポイント

- 正規化は実際の業務データを分析して、段階的に冗長性を取り除くプロセスである。
- 第1正規形：繰り返し列をなくし、主キーを設定する。
- 第2正規形：部分従属をなくし、主キーの一部だけに依存する項目を別テーブルに切り出す。
- 第3正規形：推移従属をなくし、非キー項目が別の非キー項目に依存する状況を切り離す。
- 最終的には主キーと外部キーでつながった複数の正規化テーブルになる。

## English

This week covered normalization. Using enrollment ticket data from an education management system, we practiced decomposing tables step by step from First Normal Form to Third Normal Form.

### Original Data (Non-normalized)

The enrollment ticket contains the following information, with multiple course records per student:

| Student ID | Name | Course Code | Date | Course Name | Duration | Fee | Instructor | Emergency Contact |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 200001 | Akimoto Masanori | JV21 | 6/21 | JAVA Basics | 3 days | ¥20,000 | Sano Jiro | 080-1234-xxxx |
| 200001 | Akimoto Masanori | NT21 | 6/26 | Network Basics | 2 days | ¥20,000 | Sano Jiro | 080-1234-xxxx |
| 200001 | Akimoto Masanori | UX31 | 7/11 | UNIX Basics | 1 day | ¥15,000 | Kobayashi Noriko | 090-2222-oooo |

### First Normal Form (1NF)

Remove repeating column groups and set a composite primary key (Student ID + Course Code + Date) so each row can be uniquely identified.

### Second Normal Form (2NF)

The composite primary key is Student ID + Course Code + Date. At this stage:

- Name depends only on Student ID (partial dependency) and must be separated.

Result of splitting:

- **Student table** (Student ID → Name)
- **Enrollment table** (Student ID + Course Code + Date)

### Third Normal Form (3NF)

In the 2NF state, check for transitive dependencies among non-key columns:

- Course Code → Course Name, Duration, Fee (transitive dependency)
- Instructor ID → Instructor Name, Emergency Contact (transitive dependency)

Splitting these out produces the final five tables:

| Table | Primary Key | Main Columns |
| --- | --- | --- |
| Student table | Student ID | Name |
| Enrollment table | Student ID + Course Code + Date | (relationship table) |
| Course table | Course Code | Course Name, Duration, Fee |
| Course Schedule table | Course Code + Date | Instructor ID |
| Instructor table | Instructor ID | Instructor Name, Emergency Contact |

### Key Points

- Normalization is the process of analyzing actual business data and systematically removing redundancy.
- 1NF: remove repeating columns and set a primary key.
- 2NF: remove partial dependencies by moving columns that depend on only part of a composite key to a separate table.
- 3NF: remove transitive dependencies by separating cases where a non-key column depends on another non-key column.
- The final result is multiple normalized tables connected by primary keys and foreign keys.
